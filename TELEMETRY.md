# Chargebee CLI Telemetry

The Chargebee CLI collects limited usage telemetry to help Chargebee understand how the CLI is used and where it can be improved.

Telemetry is **enabled by default** and can be disabled at any time.

Telemetry data is **pseudonymous, not anonymous**. Events include a randomly generated install ID and the Chargebee site name associated with the active profile. Telemetry never includes credentials, command values, customer data, or webhook payloads.

## First Run Essentials

On your first CLI command, a telemetry notice is displayed and **no telemetry is collected**.

Telemetry starts from your next command, giving you an opportunity to opt out before any event is recorded.

## Commands

```bash
chargebee telemetry disable          # Disable telemetry
chargebee telemetry enable           # Enable telemetry
chargebee telemetry status           # View telemetry status and install ID
chargebee telemetry status --pending # View events waiting to be sent
```

`chargebee telemetry status` also shows why telemetry is disabled when it has been turned off by an environment variable, CI environment, or unavailable local storage.

## What is Collected

The CLI normally records **one event per command**. `chargebee listen` may record multiple lifecycle events while it is running.

Telemetry is sent to a Chargebee owned endpoint. The destination cannot be changed through CLI configuration or environment variables.

A telemetry request has the following structure:

```json
{
  "client": "CHARGEBEE_CLI",
  "visitor_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "site_name": "acme-test",
  "cli_version": "1.2.8",
  "events": [
    {
      "name": "customer list",
      "timestamp": "2026-09-09T12:00:00.000Z",
      "metadata": {
        "flags": "data,fields",
        "status": "ok",
        "dur_ms": "412",
        "os": "darwin",
        "arch": "arm64",
        "rt": "node",
        "ci": "false"
      }
    }
  ]
}
```

### Fields

| Field | When collected | Description |
|---|---|---|
| `client` | Always | Identifies the event as coming from the Chargebee CLI. |
| `visitor_id` | Always | Random install ID generated by the CLI. It is not derived from your account, user, or machine. |
| `site_name` | Always | Site name of the active Chargebee profile, or `unconfigured`. |
| `cli_version` | Always | Installed CLI version. |
| `name` | Always | Command path, such as `customer list`. Arguments and values are not included. |
| `timestamp` | Always | Time the event was recorded. |
| `os` | Always | Operating system, such as `darwin`. |
| `arch` | Always | System architecture, such as `arm64`. |
| `rt` | Always | Runtime used by the CLI, such as `node` or `bun`. |
| `status` | Always | Whether the command completed with `ok` or `error`. |
| `ci` | Always | `false` for recorded events because telemetry is disabled in CI. |
| `flags` | When flags are used | Flag names only, such as `data,fields`. **Flag values are never collected.** |
| `dur_ms` | Non-interactive commands | Command duration in milliseconds. Omitted for interactive commands and `listen`. |
| `err_type` | Errors | Coarse error category such as `api_404` or `cli_error`. Error messages are never collected. |
| `pcv` | When available | Product Catalog version (`v1` or `v2`) of the configured site. |
| `code_lang` | Code generation | Generated code language, such as `go` or `js`. |
| `agent` | When detected | Supported agent runtime, such as `cursor` or `claude-code`. |
| `listen_phase` | `chargebee listen` | Tunnel lifecycle state: `established`, `closed`, or `error`. |

## What is Never Collected

Chargebee CLI telemetry does **not** collect:

- API keys, authentication tokens, or other credentials
- Command argument or flag **values**
- Customer data
- Names, email addresses, or free-form user input
- Error messages or stack traces
- Webhook event types or payloads
- Webhook forwarding URLs or session IDs

The command itself and flag **names** may be collected, but their values are never included.

## Environment Variables and CI

Telemetry is automatically disabled when:

- `DO_NOT_TRACK` is set (except `0` or `false`)
- `CHARGEBEE_CLI_TELEMETRY` is `0`, `false`, or `off`
- The CLI is running in a CI environment
- `~/.chargebee/cli` is not writable

When automatically disabled, **no telemetry is collected and no install ID is generated**.

Environment variables take precedence over CLI settings. To re-enable telemetry after `chargebee telemetry disable`, run `chargebee telemetry enable`.
